<!-- planner-discipline-allow: prefers-color-scheme -->
Write the self-test first (RED). Then the checks (GREEN).

Script shape: an ESM Node 24 script that imports only `node:fs`, `node:path` and `node:process`. It walks directories recursively with `fs.readdirSync` and `withFileTypes`, so no glob dependency is needed.

Default mode scans `dist/**/*.html` for the section rules and `src/**/*.{css,astro,ts,mjs}` plus `dist/**/*.{html,css}` for the file rules. It prints one line per violation (relative path, rule, excerpt) and ends with either "check-bands: OK (<pages> pages, <sections> sections)" and exit 0, or "check-bands: <n> violation(s)" and exit 1.

Section rules:
- Match opening `<section` tags and closing `</section>` tags in document order and track depth. Depth above 1 is nesting.
- Read `data-theme` from each opening tag with a regex that tolerates attribute order and single or double quotes.
- Alternation compares consecutive depth-1 sections within one file.

The media-feature rule matches the literal prefers-color-scheme. It skips the scripts/ directory and never scans scripts/, so this file cannot flag itself.

themes.css rule: split the file into rule blocks by selector, then check which block each palette token appears in.

`--self-test` runs each rule against in-memory fixture strings, not files. It asserts the clean fixture passes and each bad fixture yields exactly its expected rule. It prints "self-test: <passed>/<total>" and exits 0 only when all pass. It must fail if a rule function is replaced with a no-op, so each bad fixture asserts a violation count of at least 1.

Run order: `node scripts/check-bands.mjs --self-test`, then `npm run build`, then `node scripts/check-bands.mjs`. At this point dist has only the hero band, which is one light section and passes. The multi-band pages from Tasks 2 and 3 are checked in their own verify steps.
